## The payroll gate in acceptance, read from the code (P-10)

- `PayrollRunParallelCalculator.RunAsync` (`:44-57`) calls `PayrollRegimeGovernance.ValidateEmployeesAsync` for Regular and
  FinalSettlement runs while `ServiceRegimes:BlocksFinalPayroll` is true (the code default; set in no settings file). The
  run is refused when the HR.Core client is missing or any employee is blocked.
- HR.Core's `ServiceRegimePayrollBlockService` blocks an employee with an open `ServiceRegimeException`
  (`OPEN_SERVICE_REGIME_EXCEPTION`) or a current employment record (`EndDate == null`) without `LegalRegimeId`
  (`MISSING_SERVICE_REGIME`).
- `AcceptanceDataSeeder.cs:332-350` sets no `LegalRegimeId`, so every current acceptance employee is blocked by the
  second condition.
- `NationalSeedOrchestrator.ApplyIncrementalPatchesAsync` (`:89-107`, on restarts, not on the first start) ends with
  `ServiceRegimeBackfillService.SeedAsync`, which opens an `UnclassifiedRegime` exception (source Backfill) for each
  current record without a regime that the tenant filter of the default tenant shows. Whether the acceptance agencies'
  records are among them is measured on the lab stack in P5.
- `ServiceRegimeExceptionService.ResolveAsync` applies the regime through `ServiceRegimeTransitionService`
  (adds an `EmploymentRegimeTransition`, sets `LegalRegimeId`, saves), then marks the exception Resolved and saves again.
  It publishes no integration event.
- Other gates on a run: `PayrollLegalControlGuard.ValidatePayrollRelease` (first in `StartPayrollRunJobHandler`) and
  `PayrollNationalScopeGuard.ValidatePayrollPersonCount` (`PayrollRunJobHandlers.cs:97`, refuses only above the ceiling
  with `HardEnforceCeilings`). Product rules: not loosened.
- Acceptance classes that read or set a regime: `AcHcm29HireContractTests`, `AcHcm30CandidateExperienceTests` (a comment),
  `AcIam50ApproverReachDelegationTests`, `AcInt37ProductionWiringTests`, `AcMsg40AtomicPublishingTests`,
  `AcQa34PushableBaselineTests`, `AcS2s42TrustBoundaryTests`.
