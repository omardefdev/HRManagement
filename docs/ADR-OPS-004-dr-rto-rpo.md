# ADR-OPS-004 — خطة DR وRTO/RPO عبر المواقع

| الحقل | القيمة |
|---|---|
| الحالة | Accepted |
| البطاقة | OPS-004 |
| التاريخ | 2026-07-28 |

## السياق

OPS-001..003 غطّت HA داخل إقليم واحد (multi-AZ) ونسخ/PITR مع تدريبات معزولة. لا توجد خطة فقد إقليم، ولا DNS cutover، ولا موقع ثانوي، ولا مصفوفة RTO/RPO على مستوى رحلات الأعمال.

## القرار

1. **نموذج الموقع الثانوي = Warm standby** (ليس active-active في هذه البطاقة): يُرقَّى من مخزن `hrm-backups` + مانيفستات مطابقة للإنتاج.
2. **تمثيل كودي بدون Terraform:** overlays stub `deploy/k8s/overlays/dr-secondary/` و`deploy/k8s/data/overlays/dr-secondary-data/`. التوفير السحابي الحقيقي = **OPS-005**.
3. **DNS/failover:** إجراء موثّق يدوياً بموافقة Go/No-Go؛ سكربت تحقق صحة الهدف فقط (`dr-dns-cutover-check.sh`) — لا تغيير DNS آلي دون موافقة.
4. **BIA + أهداف مقاسة:** مصفوفة رحلات/خدمات في [OPS_DR_BIA_RTO_RPO.md](./OPS_DR_BIA_RTO_RPO.md) مع تمييز measured / interim / national-ceiling.
5. **Failback + reconciliation** بعد عودة الموقع الأساسي عبر سكربتات `reconcile-*` الموجودة.
6. **أوضاع متدهورة** مرتبطة بالمنصة مع إحالة الإجراءات الورقية إلى **BCP-001**؛ المنشآت إلى **PHY-001**.

## البدائل المرفوضة

| بديل | سبب الرفض |
|---|---|
| Active-active عبر إقليمين الآن | تعقيد XL + يتطلب IaC وشبكات غير موجودة (OPS-005) |
| الاعتماد على multi-AZ وحده كـ«DR» | لا يغطي فقد إقليم/موقع |
| تغيير DNS تلقائي من سكربت دون موافقة | خطر fail-open وتشغيل غير مصرّح |

## العواقب

- تدريبات tabletop + technical مطلوبة قبل إغلاق البطاقة.
- الفجوات المادية/اليدوية تُسجَّل كإحالات لـPHY-001/BCP-001 لا تُبتلع هنا.
