# PLAN-09 — المصالحة + عزل قواعد البيانات (AC-19, AC-20)

**التغطية:** AC-19, AC-20. **الطبقة:** 4. **يعتمد على:** PLAN-00.

## الهدف

إثبات أن اختلافاً متعمداً في نموذج القراءة تكشفه المصالحة وتصححه مع توثيق ما تغيّر، وأن محاولة خدمة الكتابة مباشرة في قاعدة خدمة أخرى تفشل تقنياً (التكامل عبر العقد أو الحدث فقط).

## الوضع الحالي (منفّذ / فجوة)

- منفّذ (AC-20): إنشاء أدوار وGRANT لكل قاعدة عبر [docker/init-service-roles.sh](../../docker/init-service-roles.sh) + `revoke_cross_db()`؛ سكربت إثبات [scripts/verify-postgres-service-roles.sh](../../scripts/verify-postgres-service-roles.sh)؛ سلاسل الاتصال تشير لقاعدة كل خدمة فقط؛ CAP-DB-01 "منفذ ومتحقق" (جرد + ERD).
- فجوة **AC-20**: يعتمد تطبيق الأدوار على أول إقلاع؛ غير مُشغَّل ضمن القبول/CI افتراضياً.
- فجوة **AC-19**: المصالحة قوائم تحقق يدوية فقط ([docs/FUN_004_RECONCILIATION_CHECKLIST.md](../FUN_004_RECONCILIATION_CHECKLIST.md)، [docs/REL_002_DAILY_RECONCILIATION.md](../REL_002_DAILY_RECONCILIATION.md))؛ لا مهمة آلية تكشف اختلاف نموذج القراءة (Dev.Analytics) وتصححه.

## تغييرات التنفيذ (مهام)

1. **AC-19:** مهمة مصالحة آلية لنموذج القراءة (Dev.Analytics) تكشف الاختلاف المتعمد، تصححه، وتوثّق ما تغيّر (تقرير قبل/بعد).
2. **AC-20:** تفعيل أدوار القاعدة عند إقلاع حزمة القبول، وتشغيل `verify-postgres-service-roles.sh` ضمن القبول/CI؛ إثبات فشل الاتصال العابر (مثلاً `hr_core_app` ↛ `payroll_db`).

## سيناريوهات القبول (موجب + سالب)

| AC | موجب | سالب |
|----|------|------|
| AC-19 | إحداث اختلاف متعمد ⇒ المصالحة تكشفه وتصححه مع توثيق | لا تصحيح صامت بلا توثيق |
| AC-20 | التكامل يتم عبر العقد/الحدث | محاولة كتابة مباشرة في قاعدة خدمة أخرى تفشل تقنياً |

## منهج الاختبار

مجموعة `Ac19..Ac20`؛ إعادة استخدام `Ten002ArchitecturalTests` (كمرجع)، وتشغيل سكربت أدوار القاعدة على PostgreSQL الحي.

## مخرجات الأدلة

`acceptance-evidence/AC-19/`: تقرير الكشف/التصحيح قبل/بعد. `AC-20/`: خرج `verify-postgres-service-roles.sh` يظهر رفض الاتصال العابر.

## تعريف الإنجاز

المصالحة الآلية تكشف وتصحح وتوثّق؛ الكتابة العابرة تفشل تقنياً ومُثبتة في القبول/CI؛ AC-19/AC-20 = `Pass`.
