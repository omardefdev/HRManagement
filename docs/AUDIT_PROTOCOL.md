# بروتوكول التدقيق — ما يُفحص وأين يوجد دليله

الغرض من هذه الوثيقة أن يعرف المدقق القادم سلفاً ما سيفحصه وأين يجد دليله، وأن يُمنع
عرض أي بند بلا دليل تشغيل حي على أنه مغلق.

## 1. ما يُعدّ دليلاً

الأدلة ثلاثة أنواع منفصلة، ولكل نوع تقرير مستقل. **يُحظر دمجها في رقم واحد.**

| النوع | ما هو | أين يُبلَّغ | يُحتسب في «عدد الاختبارات»؟ |
|---|---|---|---|
| اختبار سلوك | ينفّذ كود المنتج ويؤكد نتيجته | تقرير الوحدة والتكامل وE2E | نعم |
| بوابة أثر | يتحقق من بنية ملف سياسة أو manifest | خطوة سكربت في CI | لا |
| لياقة معمارية | يمسح الشيفرة بحثاً عن مخالفات | تقرير مستقل | لا (يُبلَّغ منفصلاً) |

**اختبار السلوك** يجب أن يستورد نوعاً من مشروع منتج ويستدعيه. اختبار لا يحوي `using`
لمشروع منتج ليس اختبار سلوك مهما كان اسمه.

## 2. الأمر الواحد الذي يعيد إنتاج كل النتائج

```bash
dotnet build HRManagement.slnx -c Release          # يجب: 0 خطأ
bash scripts/check-migration-discovery.sh          # يجب: كل الترحيلات قابلة للاكتشاف
dotnet test src/Tests/HRManagement.UnitTests       # سلوك
dotnet test src/Tests/HRManagement.IntegrationTests --filter "Category!=Testcontainers"
RUN_TESTCONTAINERS=true dotnet test src/Tests/HRManagement.IntegrationTests --filter "Category=Testcontainers"
RUN_PLAYWRIGHT_E2E=true dotnet test src/Tests/HRManagement.E2E
bash scripts/check-coverage.sh                     # تجميع إضافي، لا انتقاء أفضل نتيجة
```

شرط تشغيل E2E: `pwsh .../playwright.ps1 install --with-deps` قبل التشغيل، وإلا فشلت كل
الحالات المسوَّرة برسالة Playwright — وهذا سبب معروف لا يُقرأ كعيب في المنتج.

## 3. قواعد قراءة النتائج

- **صفر تخطٍّ** في المسارات الإلزامية. أي `Skip` في رحلة إلزامية يُعامل فشلاً.
- **تقرير تغطية واحد** مبني بالتجميع الإضافي. انتقاء أفضل نتيجة من عدة تقارير ممنوع،
  لأنه يسمح لناتج قديم بإخفاء انخفاض حالي.
- **الحزم المحكومة** في `coverage-floors.json` تشمل `Payroll.Application`، وهو موضع
  أخطر المنطق المالي.

## 4. البنود التي تُعرض `NOT-CLOSED` صراحةً

أي بند لا يملك دليل تشغيل حي يُعرض `NOT-CLOSED` بنص صريح، ولا يُخفى ولا يُعرض `Done`.
هذا يشمل:

- كل قرار من `SYD-001..018` لم تُصدر له أداة رسمية موقّعة.
- كل تكامل حي (خزينة، مصرف، بريد، هوية، PKI) لم تُنفَّذ دورته كاملة.
- كل بطاقة دليلها الاختباري لا ينفّذ كود منتج.

## 5. لوحة الجاهزية

نسبة الجاهزية تُشتق آلياً من نتائج CI، لا من حالة البطاقات. عدد البطاقات المغلقة ليس
مؤشر جاهزية، وقد تنخفض النسبة المعلنة مؤقتاً عند تصحيح طريقة الحساب — وهذه علامة صحة
لا تراجع.
