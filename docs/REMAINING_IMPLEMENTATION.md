## 1. ملخص تنفيذي

النظام مبني كـ **خدمات مصغّرة** مع **PostgreSQL** لكل خدمة، **MassTransit** للأحداث، و**Keycloak** في الإعدادات. **النواة (HR.Core)** و**العقود (HR.Contracts)** يمثلان أعلى نضجاً في واجهات MVC عربية (RTL). بقية الخدمات إما **شاشات أساسية** (قوائم أو CRUD جزئي) أو **بدون تغطية واجهة** لكيانات موجودة في النطاق (Domain/DbContext).

**ما يبقى بشكل جماعي:**

| المحور | وصف الفجوة |
|--------|------------|
| **عمق الوظائف** | إكمال CRUD وسير عمل وموافقات لكيانات لم تُغطَّ بعد؛ قواعد أعمال حقيقية (رواتب، سياسات إجازات، إلخ). |
| **التكامل** | استهلاك أحداث إضافية؛ تحديث **الملف المركزي** عند النقل/الفصل إن كان ذلك مطلوباً تحليلياً. |
| **البوابة والهوية** | تجربة دخول موحّدة عبر البوابة، سياسات أدوار لكل مسار، اختبار مسارات `/ui/...`. |
| **التشغيل** | فحوص صحة لكل خدمة وتجميعها؛ اختيار سياسة الترحيل في الإنتاج؛ مراقبة وربط سجلات. |
| **الجودة** | توسيع الاختبارات (وحدات، تكامل، واجهات)؛ Swagger اختياري للـ APIs. |
| **الهندسة** | تقليل تكرار القوالب عبر **Razor Class Library** إن رُغب بذلك. |

## 2. ما هو منجز باختصار (خط الأساس)

**القائمة التفصيلية المحدثة للبنية التحتية والتكامل الحديث:** [IMPLEMENTED_BASELINE.md](./IMPLEMENTED_BASELINE.md).

- **HR.Core:** وحدات تحكم متعددة (موظفون، وحدات، مؤهلات، مستندات، اتصالات، تقييمات، ملف موسّع، سجل وظيفي، سيرة معتمدة، لوحة قيادة)؛ نشر `IEmployeeCreated` و`IEmployeeStatusChanged` من مسار الموظفين.
- **HR.Contracts:** أنواع عقود، عقود (مع تفعيل و`IContractActivated`)، طلبات إجازة/سلف، مباشرة، اختبار، توقيعات، قرارات إدارية، فصل (مع `ISeparationCompleted` حسب التنفيذ)؛ مستهلك `IEmployeeCreated`.
- **HR.Movements:** طلبات نشر مع تنفيذ و`ITransferExecuted`.
- **HR.Training:** التحاق تدريب مع إكمال و`ITrainingCompleted`.
- **HR.Health:** توصيات طبية مع `IMedicalRecommendationIssued`؛ مستهلك `IEmployeeCreated`.
- **Compliance:** شكاوى؛ مستهلك `IMedicalRecommendationIssued`.
- **Payroll:** دورات رواتب وأنواع تعويضات؛ `PayrollPeriodRules` (أيام عمل/عطل/تناسب)؛ معالجة/نشر `IPayrollProcessed`؛ مستهلكون: `IContractActivated`، `ISeparationCompleted`، `ITransferExecuted`، **`ISecondmentExecuted`، `IMissionApproved`، `IDisciplinaryActionTaken`**.
- **IDCard:** تصاميم، طلبات، بطاقات مصدرة مع `ICardIssued`؛ مستهلك `IEmployeeCreated`.
- **Records.Archive / Admin.Logistics / IT.Infra / Dev.Analytics:** شاشات قائمة وتعميق جزئي؛ **IT.Infra / Dev.Analytics** يستهلكان `IEmployeeCreated` و`ISeparationCompleted`؛ **Admin.Logistics** يستهلك `ITransferExecuted` (انظر [IMPLEMENTED_BASELINE.md](./IMPLEMENTED_BASELINE.md)).
- **Auth.Directory:** مستخدمون؛ مستهلكون: `IEmployeeCreated`، `IEmployeeStatusChanged`، `ITransferExecuted`، **`ISecondmentExecuted`**؛ مزامنة Keycloak عند `DirectorySync:Enabled`.
- **Gateway:** YARP للـ API ومسارات واجهة `/ui/...`؛ لوحة مع فحص صحة حي؛ مسار فصل؛ تجميع `/health/upstreams/...`؛ انظر [IMPLEMENTED_BASELINE.md](./IMPLEMENTED_BASELINE.md).
- **ServiceDefaults:** Serilog موحّد، `TryMigrateAsync`، **MassTransit retry** (`MassTransit:RetryCount`).
- **الاختبارات:** `HRManagement.UnitTests` (~27 ملفاً)؛ `HRManagement.IntegrationTests` — مستهلكون MassTransit (15 اختباراً).

## 4. فجوات التكامل والأحداث (MassTransit)

### 4.1 ما أُنجز (2026-05)

- تسجيل المستهلكين التي كانت موجودة في الشيفرة دون `AddConsumer`: Payroll (انتداب، مهمة، تأديب)، Admin.Logistics (`TransferExecuted`)، IT.Infra وDev.Analytics (`EmployeeCreated`، `SeparationCompleted`)، Auth.Directory (`SecondmentExecuted` مع تنفيذ فعلي).
- **إعادة محاولة** MassTransit عبر الإعدادات (`MassTransit:RetryCount` / `RetryIntervalSeconds`).
- **اختبارات تكامل** للمستهلكين أعلاه + `TrainingCompletedConsumer` idempotency.
- مصفوفة محدثة: [MESSAGE_EVENT_MATRIX.md](./MESSAGE_EVENT_MATRIX.md).

### 4.2 ما يظل مفتوحاً

- **Dead-letter / outbox:** لا outbox؛ DLQ يعتمد على طوابير `_error` في RabbitMQ — راجع [RABBITMQ_OPERATIONS.md](./RABBITMQ_OPERATIONS.md).
- **Idempotency موحّدة:** أنماط marker متعددة (ليست `IntegrationMessageReceipts` على كل المستهلكين الحرجة).
- **أحداث بلا مستهلك:** `ICardIssued`، `IComplaintResolved`، أحداث HR.Contracts الداخلية الثمانية، `ISeparationStepCompleted` غير منشور.
- **versioning** رسمي للعقود عند تغيير الحقول.

### 4.3 سيناريوهات تحليلية شائعة غير مضمونة تلقائياً

| السيناريو | الملاحظة |
|-----------|----------|
| **بعد النقل** | تنفيذ في **HR.Core** و**Admin.Logistics** عبر `TransferExecutedConsumer`؛ قد يلزم توسيع السيناريوهات (سجلات إضافية، تعارض مع سجل يدوي). |
| **بعد الفصل** | إبطال بطاقة في **IDCard**؛ تعطيل دليل جزئي عبر أحداث الحالة؛ **استرداد عهدة** وإغلاق حساب كامل قد يحتاجان أحداثاً أو معالجات إضافية. |
| **Idempotency** | أنماط marker متعددة — توحيد على `IntegrationMessageReceipts` أو outbox لم يُنجز بعد. |

### 4.4 البنية التحتية للرسائل

- مراقبة **RabbitMQ** (طوابير، dead-letter) — [RABBITMQ_OPERATIONS.md](./RABBITMQ_OPERATIONS.md).
- **إعادة المحاولة** مُفعّلة في الشيفرة؛ **outbox** غير موجود.

## 9. اقتراح أولويات التنفيذ (مراحل)

الترتيب قابل للتعديل حسب أولويات الجامعة/المؤسسة.

### المرحلة أ — تشغيل وثقة

1. فحوص صحة لكل خدمة + تجميع في البوابة أو لوحة مراقبة.  
2. سياسة ترحيل واضحة للإنتاج.  
3. Correlation ID في السجلات.  
4. توسيع الاختبارات للمستهلكين الحرجة (Payroll، الفصل، العقد).

### المرحلة ب — تجربة المستخدم والهوية

1. إكمال Keycloak: دخول موحّد، أدوار، حماية مسارات `/ui`.  
2. تعميق شاشات الخدمات الثانوية (امتثال، أرشيف، لوجستيات، IT، تحليلات).  
3. معالجات فصل/نقل من طرف المستخدم تربط الخدمات بصرياً.

### المرحلة ج — أعمال حقيقية

1. محرك رواتب أو تكامل مع نظام مالي خارجي.  
2. قواعد إجازات وسلف.  
3. موافقات سير عمل (Workflow) عبر خدمة مخصصة أو محرك جاهز.

### المرحلة د — نضج هندسي

1. RCL للواجهات.  
2. Swagger حيث يلزم.  
3. توثيق مصفوفة الأحداث وإصدارات العقود.
