# FUN-002 — مسارات الاستثناء

| سيناريو | السلوك |
|---|---|
| تاريخ نفاذ مستقبلي | إنشاء السجل مسموح؛ **التنفيذ مرفوض** حتى `EffectiveDate <= اليوم` **بتوقيت دمشق** (PLAN-60)، برسالة تذكر التاريخين |
| إلغاء من «مسودة» أو «مرفوض» | انتقال إلى «ملغى» **بسبب إلزامي**؛ السجل يبقى للتاريخ (`IsCancelled`) — **لا حذف أبداً** (أُزيل إجراء الحذف) |
| إلغاء من «بانتظار الاعتماد» | يُسحب الاعتماد من محرك سير العمل أولاً (`CancelAsync`)؛ إن كان قد انتهى تُطبَّق نتيجته ثم يُحكم على الطلب من جديد بالحالة الناتجة |
| إلغاء من «معتمد» | انتقال إلى «ملغى» بسبب؛ لا saga بعد. القرار الإداري الصادر **يبقى مرتبطاً بالسجل للتاريخ** (القرار التصحيحي من الموجة الثانية) |
| إلغاء من «قيد التنفيذ» أو «بانتظار تدخل» أو «مكتمل» | **مرفوض** في هذه الخطة: «إلغاء فصل قيد التنفيذ يتطلب مسار التعويض (PLAN-63)» |
| Legal Hold | الإنشاء والتقديم والتنفيذ مرفوضة عبر `IEmployeeLifecycleGate` (fail-closed: تعذّر التحقق = رفض) |
| موظف انتهت خدمته أو غير موجود | الإنشاء مرفوض برسالة تسمي الحالة (PLAN-60) |
| طرف معطل / timeout | السجل «بانتظار تدخل» (`SeparationInterventionStatusConsumer`) + ProcessInterventions؛ Resume بعد الإصلاح يعيده «قيد التنفيذ». **إلغاء التدخل مرفوض لفصل** حتى PLAN-63 (يبقى لتعيين كما كان) |
| استئناف (Appeal) | تصحيح الطرف ثم Resume — لا حذف تاريخ |
| إعادة توظيف (Rehire) | SeparationRecord (ملغى أو مكتمل) يبقى؛ تعيين لاحق عبر FUN-001 |
| تسوية مرحّلة Posted خاطئة | خارج saga — استخدم PAY-003 Reverse |
| NationalId / بيانات هوية | تصحيح عبر DATA-002؛ لا يعيد فتح فصل مكتمل تلقائياً |

قناة التدخل الدنيا: `GET/POST /api/process-interventions` على HR.Contracts.
