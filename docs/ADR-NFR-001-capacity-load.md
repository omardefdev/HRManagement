# ADR-NFR-001 — نموذج سعة واختبارات load/soak/stress

| الحقل | القيمة |
|---|---|
| الحالة | Accepted |
| البطاقة | NFR-001 (البطاقة 39) |
| التاريخ | 2026-07-28 |

## السياق

منصة PERF-001..004 وOPS-002 وOBS-002 (J1–J4) جاهزة، لكن بلا نموذج حمل موثّق، بلا بيانات اصطناعية قابلة للتكرار، وبلا سيناريوهات load/soak/spike/stress مربوطة بـSLO. القياس الوطني الكامل (5M / 72h) مؤجّل لـCAP-001.

## القرار

1. **الأداة:** k6 تحت [`perf/k6/`](../perf/k6/)؛ التشغيل عبر Docker `grafana/k6` أو تثبيت محلي؛ أغلفة `scripts/nfr-k6-run.*`.
2. **فصل النطاق:** NFR-001 = منهجية + نموذج + نتائج مخبرية قابلة للمقارنة (10k payroll إلزامي؛ 100k عند توفر staging). مغلف CAP (72h@100% / 4h@150% / 15m@200% على الحجم الوطني) = **CAP-001**.
3. **عامل تصغير `scale_factor`:** التشغيل المخبري = المغلف الوطني × scale_factor (افتراضي `0.002` → ~10k موظف من 5M).
4. **عتبات تحت الحمل:** مشتقة من [OBS_SLO_CATALOG.md](./OBS_SLO_CATALOG.md) — J2 P95 &lt; 2s؛ J4 fail &lt; 1%؛ J3 outbox ضمن العتبات أثناء العاصفة؛ لا نمو غير محدود للذاكرة/الاتصالات/الطوابير على نافذة soak.
5. **Soak مخبري:** ≥2 ساعة @100% نموذج NFR؛ امتداد 72h موثّق كإجراء CAP فقط.
6. **NTP / التكرار:** ساعة الخادم متزامنة؛ نفس seed ونفس profile يعيدان نتائج ضمن تسامح ±15% للزمن/المعدل.
7. **CI:** smoke k6 فقط (مدة قصيرة، عتبات رخوة)؛ الأحمال الكاملة خارج PR على staging/lab.
8. **خارج النطاق:** فوضى التبعيات → **NFR-002 Done** ([ADR-NFR-002-chaos-recovery.md](./ADR-NFR-002-chaos-recovery.md))؛ إعادة كتابة محرك الرواتب؛ 5M/72h كشرط إغلاق.

## العواقب

- CAP-001 وSYR-002 يستهلكان النموذج والهارنس دون إعادة بنائهما.
- تقرير 24 شهراً وbottleneck budget يغلقان معيار القبول في backlog.
