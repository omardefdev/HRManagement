# الخطة الرئيسية لاستكمال HRManagement

## القرار الهندسي الحاكم

التسلسل الإلزامي هو: **إغلاق التعرض الأمني → تثبيت صحة الأعمال والبيانات → إثبات الاتساق والعزل → استكمال قدرات المنتج الوطني → الهجرة والتكامل → إثبات الاعتمادية والحجم والسيادة → Pilot مضبوط → اعتماد مستقل → إطلاق وطني بالموجات**. البطاقات الـ58 الأصلية هي النواة الهندسية، وليست وحدها تصريح إنتاج وطني.

```mermaid
flowchart LR
    P0["P0: منع الاختراق والفساد"] --> P1["P1: عزل وصحة أعمال وبيانات"]
    P1 --> P2["P2: توسع وHA وDR"]
    P2 --> P3["P3: جودة وحوكمة واكتمال وظيفي"]
    P3 --> NP["برنامج المنتج والهجرة والتكامل الوطني"]
    NP --> STG["Staging مماثل للإنتاج"]
    STG --> PILOT["Pilot لجهة واحدة"]
    PILOT --> P4["P4: ضمان وسيادة واعتماد مستقل"]
    P4 --> WAVES["إطلاق وطني بالموجات"]
    WAVES --> NAT["تشغيل وطني واعتماد مستمر"]
```

## بوابات القرار

| البوابة | شروط العبور المختصرة | القرار عند الفشل |
|---|---|---|
| G0 — Safe to Develop | لا أسرار متداولة، لا منافذ حساسة عامة، بيئة تطوير آمنة، وسلسلة توريد قابلة للبناء داخلياً | إيقاف أي نشر مشترك |
| G1 — Safe for Synthetic Staging | إغلاق P0، CI صادق، auth وdeployment يعملان من الصفر، وخط أساس زمني معتمد | لا بيانات حقيقية |
| G2 — Safe for Single-Agency Pilot | tenant وعزل الكائنات، maker/checker، رواتب قابلة للإعادة، restore ناجح | Pilot ببيانات مصطنعة فقط |
| G3 — Safe to Scale | HA/DR، load/soak، SLO، تدقيق durable، اختبار اختراق | لا إضافة جهات جديدة |
| G4 — Production Candidate | اكتمال القدرات والهجرة والتكامل ونجاح Pilot وتشغيل 24/7 | لا موجات وطنية |
| G5 — National Authorization | نجاح `NAT-001..008` واعتماد مستقل للنسخة والبيئة | قرار No-Go موثق |
| G6 — Wave Go/No-Go | نجاح شروط `REL-007/ONB-002` لكل جهة أو موجة | إيقاف الموجة أو التراجع |

## توزيع العمل المقترح

لا يُنصح بتقسيم الفرق حسب طبقات تقنية فقط. التوزيع الأنسب:

- فريق أمن وهوية وعزل: `SEC`, `IAM`, `TEN`.
- فريق صحة أعمال وبيانات: `DOM`, `PAY`, `DATA`, `FUN`.
- فريق تكامل وملفات: `INT`, `FILE`.
- فريق منصة وتشغيل: `DEP`, `DB`, `OPS`, `OBS`, `SUP`, `PHY`.
- فريق جودة وتجربة وحوكمة: `QA`, `UX`, `GOV`, `REL`, `L10N`.
- مكتب المنتج والهجرة والتكامل: `STR`, `PRD`, `MDM`, `HCM`, `WF`, `MIG`, `EXT`, `INT`, `ONB`, `DEC`.
- مكتب الضمان الوطني: `SOV`, `EVD`, `PRV`, `LEG`, `SCM`, `NAT`, `FRD`.
- مكتب التوطين والاعتماد السوري: `SYR` و`SYD` بالتنسيق مع الوزارات والهيئات والمؤسسات المالكة للنص والبيانات.
- مكتب إدارة البرنامج والمشتريات: `PGM`, `SAN`, `FIN`, `TRN` بالتنسيق مع الجهة المالكة والمشتريات وممثلي العاملين.

كل فريق يملك اختبارات التشغيل والمراقبة والتوثيق لعمله؛ لا تُرحّل هذه المسؤوليات إلى فريق QA في نهاية الدورة.

## سياسة التغيير في النطاق

أي ميزة جديدة لا تعالج مانعاً أو شرط اعتماد توضع بعد البطاقات الحالية، ما لم يعتمد مجلس المنتج تغيير الأولوية ويُوثّق أثره. لا يجوز حذف معيار قبول لتسريع الإغلاق؛ يمكن تقسيم البطاقة فقط مع إبقاء البوابة مغلقة حتى اكتمال جميع الأجزاء. كل بطاقة `XL` برنامج صغير يجب تفكيكه إلى Stories قبل التنفيذ مع بقاء معاييرها كمعيار إغلاق للـEpic.
